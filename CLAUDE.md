# Alchemist Labeler

Standalone TS/React tool for producing `manual_v1` label_set JSON to feed
`signal-substrate-v1` 阶段 b. UI side only — calibrator consumption lives in
the alchemist main repo.

Parent task: [docs/tasks/signal-substrate-v1-stage-a-labeler.md](../alchemist/docs/tasks/signal-substrate-v1-stage-a-labeler.md)
in the alchemist repo (sibling directory).

Run cookbook + prerequisites: see [README.md](README.md).

## Cross-repo boundary

This repo is **independent of alchemist**. The only coupling is JSON files
flowing in both directions:

```
alchemist (tools/pl-export, opt-in C++)             alchemist-labeler (this repo)
    │                                                       │
    │  --out=<file.json>                                    │
    └──> public/precomputes/<window_id>.json  ──fetch──>    │
                                                            │  UI
    alchemist/tests/support/strategytester/                 │
    manual_v1/   <── manual cp/symlink ────────  labels/<window_id>.manual_v1.json
```

No build coupling. No shared library. No Node ↔ C++ runtime link.

## Locked decisions (Step 1)

| # | Decision | Choice | Implication |
|---|---|---|---|
| A | C++ pre-compute CLI location | `alchemist/tools/pl-export/` (opt-in) | Single subdir with its own CMakeLists. NOT included in default `add_subdirectory` chain. Build via `-DBUILD_PL_EXPORT=ON`. Must not change `StrategyTester` / `alchemyd` default build. |
| B | Data delivery | Static JSON, zero server | UI does `fetch('./precomputes/<window_id>.json')`. No Node/Python server. Pre-compute writes once per IS window, UI re-reads on load. |
| C | Label JSON destination | `alchemist-labeler/labels/` (gitignored) | Self-contained in this repo. Manual `cp` to `alchemist/tests/support/strategytester/manual_v1/` when feeding 阶段 b. |
| D | Single vs multi labeler | Single labeler in v1; schema records `reviewer_id` / `labeler_id` (`betachen`) | Multi-labeler workflow (kappa, agreement) deferred. Schema does not lock out future multi. |

## window_manifest (Step 1 schema, frozen)

Manifest is the **only** entry point for window selection. UI refuses any
`{start_ms, end_ms}` not resolvable via `window_id`.

Filesystem: `alchemist-labeler/public/manifests/<manifest_version>.json` (checked into git)
Served at:  `/manifests/<manifest_version>.json` (Vite serves `public/` at root URL)
Launch:     `?manifest=<version>&window_id=<id>`

```json
{
  "manifest_version": "is-windows-2023-2024-v1",
  "pl_proposal_version": {
    "code_git_sha": "<sha of alchemist tools/pl-export at run time>",
    "smaPeriod": 120,
    "turningPointPeriod": 10
  },
  "windows": [
    {
      "window_id": "btcusdt-15m-2023-02",
      "market": "BTCUSDT",
      "interval": "15m",
      "is_range": { "start_ms": 1675209600000, "end_ms": 1677628800000 },
      "precompute_path": "precomputes/btcusdt-15m-2023-02.json"
    }
  ],
  "content_hash_sha256": "<sha256 of canonical-serialized object minus this field>"
}
```

UI startup contract (implemented in [src/hooks/useSessionBootstrap.ts](src/hooks/useSessionBootstrap.ts)):
1. Validate `?manifest=`/`?window_id=` shape (`[a-zA-Z0-9._-]+` only — no path traversal).
2. Load `/manifests/<id>.json`; recompute `content_hash_sha256` over canonical-serialized object minus that field; compare. Mismatch → refuse.
3. Resolve `?window_id=` against `manifest.windows[]`. Not found → refuse.
4. Fetch `/<precompute_path>`. Cross-check precompute `is_range` against manifest window `is_range`. Mismatch → refuse.
5. Time-axis lock: `fixLeftEdge` + `fixRightEdge` + `lockVisibleTimeRangeOnResize` on the chart — user can pan/zoom within the IS range, can't drag past the edges into empty OOS area. Defense-in-depth bar-range assertion also rejects any bar with `ms ∉ is_range`.

Content-Type discrimination: Vite dev returns the SPA fallback (`index.html`)
for any missing path, including `.json`. The fetch helper guards against this
by checking `Content-Type: application/json` before parsing — a missing
manifest/precompute surfaces as a clear "file does not exist" refusal, not a
JSON parse error.

Storage layout:
- `public/manifests/` — checked into git (IS-window registry)
- `public/precomputes/` — gitignored (regenerated by `alchemist/tools/pl-export`)
- `labels/` — gitignored (reviewer output, not served)
- `scripts/sign-manifest.mjs` — re-computes and writes back `content_hash_sha256` for a manifest file. Run after editing any manifest. Canonical-serialization algorithm MUST stay in lockstep with [src/lib/canonicalJson.ts](src/lib/canonicalJson.ts).

## Segment state machine

```
            U/O/P/S (assignLabel)
unreviewed ───────────────────────► human_prelabel
    ▲                                     │
    │                                     │ R (revealCurrent)
    │ D (rejectCurrent)                   ▼
    │  sets was_rejected=true       overlay_revealed
    │  reject_count++                     │
    └─────────────────────────────────────┤
                                          │
                          ┌───────────────┼───────────────┐
                          │               │               │
                       A (accept)     E + ←/→ + Enter   D (reject)
                          │           (boundary edit)
                          ▼               ▼
                       accepted         edited
                          (terminal — reviewed_at_ms set)
```

Implementation rules (enforced by guards in
[labelSessionStore.ts](src/stores/labelSessionStore.ts)):

- `assignLabel` is only allowed in `unreviewed` or `human_prelabel`. Once
  `overlay_revealed`, you must `D` first (load-bearing invariant #2: no
  re-labeling after seeing PL/HT).
- `revealCurrent` only fires from `human_prelabel` (you must have a tentative
  label before you can peek).
- `enterEdit` only from `overlay_revealed`, and not on the last segment
  (its end is the manifest `is_range.end_ms` — would push past the boundary).
- Navigation (`←/→`, `N`) is blocked while `edit.active`.
- Boundary edits clamp to `(segStart + 1 bar, nextEnd - 1 bar)` — neither
  this nor the next segment may degenerate.
- `commitEdit` distinguishes no-op (same as `acceptCurrent`, → `accepted`)
  vs real shift (→ `edited`).
- `reviewed_at_ms` is set on transition INTO `accepted` / `edited`; cleared
  on transition INTO `unreviewed` via reject. Untouched on any other action.
  This is the determinism anchor for export (Step 8).

Display rule: `accepted && was_rejected → 'rejected_then_relabeled'` (see
`terminalDisplayState` in [types/segment.ts](src/types/segment.ts)). On
export, `source` carries the same three-way mapping. `edited && was_rejected`
stays `edited` — `was_rejected` is a separate signal preserved alongside.

## Hotkeys

Mounted globally via [useLabelHotkeys.ts](src/hooks/useLabelHotkeys.ts).
Ignored while typing in `INPUT` / `TEXTAREA`. Gated on `status === 'ready'`.

| Key | Normal mode | Edit mode |
|---|---|---|
| `U` / `O` / `P` / `S` | label uptrend / oscillation / pullback / sideways | (ignored) |
| `R` | reveal overlay for current segment | (ignored) |
| `A` | accept current | (ignored) |
| `D` | reject current (sets `was_rejected`, clears `reviewed_at_ms`) | (ignored) |
| `E` | enter edit-boundary mode | — |
| `Esc` | — | cancel edit |
| `Enter` | (ignored) | commit edit |
| `←` / `→` | prev / next segment | shift end by ±1 bar |
| `N` | jump to next `unreviewed` segment | (ignored) |
| `Space` | global overlay peek (debug — does NOT advance state machine) | toggle peek |

The Space peek is independent of the per-segment state machine and exists for
reviewer sanity-checking; it must not be relied upon as the workflow reveal
(load-bearing invariant #2 — see below).

## Coverage gate

Pure math: [src/lib/coverage.ts](src/lib/coverage.ts). UI:
[src/components/CoverageGate.tsx](src/components/CoverageGate.tsx).

Bar count per segment is half-open: `(effective_end - effective_start) / barStepMs`.
Adjacent segments share a boundary, so half-open avoids double-counting.

Floors (constants in [coverage.ts](src/lib/coverage.ts) — sourced from
signal-substrate-v1.md `label_set` schema; keep in lockstep):

| Floor | Threshold | Why |
|---|---|---|
| `n_uptrend` | ≥ 100 bars | each active state needs enough samples for calibration mean/stddev |
| `n_oscillation` | ≥ 100 bars | same |
| `active_coverage` | ≥ 0.30 of labelable bars | active states must cover enough of the window to bound regime drift |
| `all_terminal` | every segment in `accepted` ∪ `edited` | no `unreviewed` / `human_prelabel` / `overlay_revealed` allowed |

`pullback` + `sideways` are `labeled_inactive` — they count toward
"every segment is labeled" (via `all_terminal_ok`) but **do not** appear in
`active_coverage`'s numerator. This is invariant #5: the export gate cannot
be gamed by spamming inactive labels.

## Export determinism

Built by [src/lib/exporter.ts](src/lib/exporter.ts). Schema matches
signal-substrate-v1.md §"label_set JSON schema" verbatim.

The export contract:

- `content_hash_sha256` is computed over the canonical-serialized object with
  `content_hash_sha256: ""` substituted in. Same convention as the manifest
  hash (Step 3). Downstream consumers verify by canonical-serializing with
  the field zeroed and re-hashing.
- `created_at_utc = max(reviewed_at_ms across all segments)`. Stable across
  consecutive exports with no intervening label mutation; flips when any
  segment is re-labeled.
- Per-segment `reviewed_at_utc` is locked at the time the segment first
  reaches `accepted` / `edited`; only `D` (reject) resets it.

Together these mean: two consecutive Export clicks with no label edits
produce byte-identical canonical strings AND byte-identical hashes. Any
label / boundary / state change flips the hash.

The downloaded file is pretty-printed (2-space indent) for human diffability;
the hash is computed over the CANONICAL form, not the pretty form, so the
consumer must re-canonicalize before verifying.

## Six load-bearing UX invariants

Sourced from [signal-substrate-v1.md §"Six load-bearing UX decisions"](../alchemist/docs/tasks/signal-substrate-v1.md).
Concrete enforcement points in this codebase:

1. **PL is never a label by default.** The 4-label vocabulary (`uptrend` /
   `oscillation` / `pullback` / `sideways`) is set by the reviewer, not by
   PL. PL slope is shown post-reveal as one of two diagnostic overlays.
   Enforced by: `assignLabel` requires explicit `U/O/P/S` keystroke.
2. **Anchoring mitigation (先判后看).** The state machine forces
   `unreviewed → human_prelabel → overlay_revealed → terminal`. Per-segment
   overlay rendering: `visible = state ∈ {overlay_revealed, accepted, edited}`.
   Enforced by:
   [KlineChart.tsx](src/components/chart/KlineChart.tsx) per-segment
   visibility loop + state-machine guards in the store. (Space peek is a
   debug bypass that doesn't advance state.)
3. **HT_TRENDLINE second-opinion overlay.** Continuous real-valued
   instantaneous trendline (Hilbert transform), price-scale-comparable to
   PL. Rendered as a per-segment line series alongside PL. Visibility tied
   to the same per-segment state as PL.
4. **OOS range hard-blocked.** Manifest is the only entry point;
   `is_range` is checked at fetch time (precompute cross-check) and at
   chart-axis level (`fixLeftEdge` / `fixRightEdge`). Defense-in-depth
   bar-range assertion in [useSessionBootstrap.ts](src/hooks/useSessionBootstrap.ts).
5. **Coverage targets enforced before export, computed over ACTIVE labels
   only.** See "Coverage gate" above. Inactive labels (`pullback`,
   `sideways`) appear in the denominator (`labelable_bars`) but not in the
   numerator (`active_labeled_bars`) — so flipping a segment from `null`
   to `pullback` leaves `active_coverage` unchanged.
6. **Reviewer provenance + version pinning.** Export schema carries
   `labeler_id`, per-segment `reviewer_id`, `reviewed_at_utc`,
   `pl_proposal_version.code_git_sha`, `label_set_version: manual_v1`,
   `content_hash_sha256`. Downstream `CalibrationArtifact v4` references
   `label_set_version` + `label_set_hash` so verdicts trace back to the
   exact labeled file.

Any future change in this repo that touches segment / state / export logic
must re-verify these six.
